# Чеклист понимания: One Shape

Отмечай пункт, когда ты объяснил его своими словами и ответил на вопрос по нему.

## 1. Проблема
- [ ] Зачем «одна фигура без склеек» и почему она сложнее набора отдельных анимаций.
- [ ] Почему нельзя использовать CSS transitions и таймеры при рендере кадр-за-кадром (кадр = снимок в момент `t`, у браузера нет «прошлого кадра»).
- [ ] Почему цикл 14,000 с требует ровно 120 BPM (840 кадров — целое число; 119 BPM дал бы 847,06 кадра и рывок на стыке).
- [ ] Ветки решения, которые мы отвергли: CSS-анимации + запись экрана; накопление состояния между кадрами; растягивание анимации под 119 BPM вместо растягивания звука.

## 2. Решение
- [ ] Формула пружины `S(τ)`: что делают `f` (время отклика) и `z` (демпфирование), откуда перелёт 1,5 %.
- [ ] Сумма пружин: почему смена цели = добавить ещё одну ступеньку.
- [ ] `ptrack`: зачем суммировать прошлый цикл (`t − e.t + T`) и почему это даёт совпадение позиции и скорости на стыке.
- [ ] `chain`: как отпускание после драга стартует с позиции и скорости драга (`R(τ, x0, v0, …)`).
- [ ] Два края индикатора на разных пружинах → «жидкое» растяжение; почему ведущий край меняется при смене направления.
- [ ] Резинка за максимумом: `78·(1 − 1/(1 + over/110))` — почему функция насыщается.
- [ ] Палитра: верх палитры стоит на месте, потому что `CY` и `H` на одной пружине.
- [ ] Текст внутри морфа: у каждого слоя свой вход/выход, вход позже выхода → нет наложения.
- [ ] Курсор в экранных координатах, цели в мировых; почему курсор не растёт при зуме.
- [ ] Звук: спектральный поток → темп → фаза → сильная доля; rubberband + повторный замер (сдвиг 16 мс).
- [ ] Motion blur: 4 подкадра на кадр → `tmix` → `select`.
